# Known Selector Patterns — Reference

Load this file **before** writing Playwright assertions in Step 6, and re-check after every script generation. Patterns below are battle-tested against shadcn / base-ui / Next.js / Tailwind in this monorepo.

| Scenario | ❌ Wrong | ✅ Correct | Reason |
|----------|----------|------------|--------|
| Page heading in `beforeEach` | `getByText('Page Title')` | `getByRole('heading', { name: '...', level: 1 })` | Same text appears in sidebar nav → strict-mode violation |
| `.or()` locator assertion | `a.or(b).toBeVisible()` | `a.or(b).first().toBeVisible()` | Both sides can match simultaneously in optimistic-update UIs → strict-mode violation |
| `[role="alert"]` in Next.js | `page.locator('[role="alert"]')` | `page.locator('[role="alert"][data-slot="alert"]')` | Next.js route announcer also has `role="alert"` |
| Keyboard nav on listbox | `getByText(label).focus()` | `getByRole('option', { selected: true }).focus()` | Text spans are not focusable; `keydown` handler is on the listbox/option |
| User menu (ShadCN sidebar) | `button:has-text("admin")` | `locator('[data-sidebar="footer"]').locator('button').first()` | Display name varies per user profile |
| Section heading in position tests | `getByRole('heading', { level: 2 }).first()` | `getByRole('heading', { name: 'Known Text' })` | `.first()` picks DOM-order first, not the intended element |
| ShadCN Card buttons (multiple cards, same label) | `getByRole('button', { name: 'Claim' })` | `locator('[data-slot="card"]').filter({ hasText: 'Task Name' }).getByRole('button', { name: 'Claim', exact: true })` | Multiple cards share "Claim" label → strict-mode violation; scope to card first |
| Card with text-only filter (ambiguous) | `locator('[data-slot="card"]').filter({ hasText: 'Email' })` | `locator('[data-slot="card"]').filter({ has: page.locator('[data-slot="card-title"]', { hasText: /^Email$/ }) })` | `hasText` matches any descendant — anchored regex on the title slot avoids cross-card collisions |
| base-ui Sheet open check | `getByRole('dialog')` | `locator('[data-slot="sheet-content"]')` | `@base-ui/react` Dialog Popup does NOT use `role="dialog"` — it renders with `data-slot="sheet-content"` |
| base-ui Sheet title | `locator('[data-slot="sheet-title"]')` (global) | `locator('[data-slot="sheet-content"]').locator('[data-slot="sheet-title"]')` | Scope sheet-title inside sheet-content to avoid false positives when sheet is closed |
| Sheet has duplicate Close button | `sheet.getByRole('button', { name: 'Close' })` | `sheet.locator('[data-slot="sheet-footer"]').getByRole('button', { name: 'Close' })` | The auto-injected `[data-slot="sheet-close"]` X-icon shares accessible name "Close" with the footer button — scope to footer |
| Two badges in same card share text | `card.locator('[data-slot="badge"]').filter({ hasText: 'Disabled' })` | `card.locator('[data-slot="badge"][data-variant="secondary"]').filter({ hasText: 'Disabled' })` | When an enabled/disabled badge and an after-hours badge both render "Disabled", differentiate by `data-variant` (or scope to CardHeader vs CardContent) |
| react-resizable-panels Panel id | `locator('[data-panel-id="str-detail"]')` | `locator('#str-detail')` | `react-resizable-panels` renders the `id` prop as HTML `id` attribute, NOT `data-panel-id` |
| Free-text vs markdown text collision | `getByText('Milestone Name')` | `locator('p').filter({ hasText: /^Milestone Name$/ })` | Charter markdown `<li>` and milestone `<p>` both contain same text → strict-mode; scope to `<p>` |
| Next.js SSR sheet/modal click | `page.goto(...); button.click()` | `page.goto(...); page.waitForLoadState('networkidle'); button.click()` | Click fires before React hydration completes; `domcontentloaded` is insufficient for controlled-state components |
| Unauthenticated test via `browser.newContext()` | `await browser.newContext()` | `await browser.newContext({ storageState: { cookies: [], origins: [] } })` | When the project's `use.storageState` points to a valid `.auth/user.json`, `newContext()` inherits the auth — the "unauth" test silently passes through as authenticated |
| ShadCN/Radix date picker | `page.locator('input[type="date"]').fill('2026-06-15')` | `page.locator('#field-id').click(); page.getByRole('gridcell', { name: '15' }).click();` | Date "input" is rendered as a `<button data-slot="popover-trigger">` opening a calendar popover. `.fill()` errors with "Element is not an `<input>`" |
| Double-click prevention test | `await btn.click(); await btn.click({ force: true });` | `await btn.click(); await btn.click({ timeout: 1000 }).catch(() => {});` | `force: true` bypasses the disabled-state check and ALWAYS sends a second event, defeating the test purpose |
| Relative timestamp assertions ("Xh ago") | `expect(row.getByText('3h ago')).toBeVisible()` | `expect(row.getByText(/\d+\s*(h\|d)\s*ago/i)).toBeVisible()` | Real timestamps drift between captures — always regex unless the test seeds the timestamp explicitly |
| Badge color (Tailwind custom `className`) | `expect(page.getByText('Production')).toBeVisible()` | `const badge = card.locator('[data-slot="badge"]').filter({ hasText: 'Production' }); await expect(badge).toHaveClass(/bg-green-500/);` | Text-only check passes even when wrong color — the color IS the spec requirement |
| Badge color (shadcn `variant` prop, no custom className) | `expect(badge).toBeVisible()` | `const badge = locator('[data-slot="badge"][class*="destructive"]'); await expect(badge).toBeVisible();` | Shadcn injects the variant token into `class` — assert via attribute selector |
| Badge color — wrong card scoping | `page.locator('[data-slot="badge"]').filter({ hasText: 'Production' }).first()` | `card.locator('[data-slot="badge"]').filter({ hasText: 'Production' })` (scoped to the specific card) | `.first()` picks DOM-order first globally — always scope to the parent card |
| Sequential mock responses for retry | `let calls=0; if(++calls===1) return 500; return 200;` | `let shouldFail=true; if(shouldFail) return 500; return 200; /* flip shouldFail=false before retry click */` | TanStack Query auto-retries on 5xx — call counters become non-deterministic. Use a flag flipped at the user-action synchronisation point |
